# Hunter × Hunter Archive — Implementation and Maintenance Handbook

Current contract: Cloudflare HxH deployment · Batch 12 design system · July 23, 2026

- Maintained story boundary: Chapter 413
- Factual source boundary: Hunterpedia / Fandom only
- Reader-facing route inventory: 26 reader-facing screens
- Priority local media: 106 character portraits and 29 Black Whale derivatives
- Runtime: Cloudflare Worker plus `ASSETS`

## Architecture

The application has four top-level workspaces: Home, Series, Succession, and Reference. `src/data/routeManifest.js` owns the route inventory and aliases. `src/App.jsx` owns the lightweight shell and lazy rendering. `src/lib/appRouter.js` owns clean history paths, query preservation, direct reload behavior, and migration of old hash links.

Cloudflare executes `dist/server/index.js`; browser assets are served from `dist/client/`. `server/index.js` handles the administrator and `/api/admin/chapter/*` before the static binding, then applies the SPA fallback only to ordinary HTML navigation.

The global CSS order is `src/styles.css`, `src/nen.css`, and `src/styles/final-polish.css`. The final identity remains a black shell, warm paper, crimson active states, antique gold metadata, steel blue information, and selective purple.

## Content schema

Principal structured owners:

- `src/data/systemsDesk.js` — organizations, relationships, and object trails.

Update canonical records before their visual consumers. The complete character directory remains intact; richer dossiers are additive overlays.

## Source and evidence contract

Hunterpedia/Fandom is the only factual and image-source boundary unless the owner explicitly changes that policy.

- `src/data/bibliography.js` owns reusable source records.
- `src/data/evidenceStates.js` owns evidence vocabulary.
- `src/data/reviewQueue.js` owns blocked and incomplete work.
- `src/data/sourcePolicy.js` owns approved hosts.
- `src/schema/` contains machine-readable content contracts.

Keep facts, archive analysis, unresolved material, and medium-specific notes visibly separate. Never complete an unknown state by inference.

## Media and status rules

`src/data/characters.js` owns portrait provenance. `src/data/priorityMedia.generated.js` mirrors the stabilized local portrait records and is regenerated by `scripts/stabilize-media.mjs`.

`src/data/blackWhale.js` owns room-image provenance. `src/data/blackWhaleMedia.generated.js` mirrors the stabilized derivatives and is regenerated by `scripts/stabilize-room-media.mjs`.

`src/data/mediaRegistry.js`, `src/data/mediaSchema.js`, and `src/components/SafeImage.jsx` enforce local, verified-remote, and text-only states. Missing media must collapse without fake imagery. A red X is reserved for confirmed death and requires written status.

## Accessibility and responsive behavior

Maintain skip navigation, visible focus, menu and dialog containment, Escape dismissal, keyboard tab systems, named scroll regions, live announcements, reduced motion, contained tables and media, the 11px explicit type floor, and the 44px touch-target contract.

Static owners include `scripts/audit-readability.mjs`, `scripts/audit-layout.mjs`, and `scripts/audit-accessibility.mjs`. Browser verification remains a separate evidence-producing workflow.

## Performance boundaries

`src/data/performanceBudgets.js` owns these limits:

- application entry: 500,000 bytes;
- startup JavaScript closure: 1,000,000 bytes;
- startup CSS: 1,000,000 bytes;
- largest JavaScript chunk: 750,000 bytes;
- local portrait: 160,000 bytes;
- portrait library: 2,200,000 bytes.

The production manifest retains 21 dynamic entries. `src/lib/routePreload.js` owns direct UI loaders and the three `src/data/archiveSearch.*.js` files own the search shards.

## Aggregate build preflight

`scripts/run-build-preflight.mjs` runs 15 independent pre-build audits and reports the complete repair list. The Cloudflare build then creates `dist/client/`, applies performance validation, prepares `dist/server/`, and runs the Cloudflare release audit.

Retired portable source ZIPs, standalone builds, release manifests, and OpenAI hosting identities are forbidden from the deployed artifact.

## Update runbooks

### 1. New chapter endpoint
Canonical owner: `src/data/chapterTitles.js`. Reconcile `src/data/chapters.js` and `src/data/archiveMeta.js`, then update current-arc records and all chapter boundaries.

### 2. Chapter research revision
Canonical owner: `src/data/chapters.js`. Preserve the difference between chapter-specific evidence and arc-phase context.

### 3. Character identity or status
Canonical owner: `src/data/entityRegistry.js`. Update aliases and status centrally before encyclopedia, roster, tree, or dossier consumers.

### 4. Character portrait
Canonical owner: `src/data/characters.js`. Run `npm run stabilize:media`, inspect the generated record, then run the media audit.

### 5. World or location record
Canonical owner: `src/data/worldAtlas.js`. Preserve stable IDs, hierarchy, route links, source, and readable alternatives.

### 6. Black Whale space or route
Canonical owner: `src/data/blackWhale.js`. Reconcile hotspot, inspector, room ledger, occupancy, access, and chronology references.

### 7. Succession chronology event
Canonical owner: `src/data/successionTimeline.js`. Record chapter, time confidence, location, participants, result, and consequence.

### 8. Nen mechanic or ability
Canonical owner: `src/data/nenEncyclopedia.js`. Separate confirmed mechanics, conditions, costs, counters, inference, and unknown rules.

### 9. Faction, relationship, or object trail
Canonical owner: `src/data/systemsDesk.js`. Preserve direction, type, time scope, custody, authority, current state, and source.

### 10. Route or navigation change
Canonical owner: `src/data/routeManifest.js`. Reconcile `src/App.jsx`, `src/lib/appRouter.js`, navigation, direct reload, accessibility, and bundle boundaries.

### 11. Layout or readability defect
Canonical owner: `src/styles.css`, with final overrides in `src/styles/final-polish.css`. Run static layout checks and browser QA before declaring the defect closed.

### 12. Design-system primitive or tone
Canonical owner: `src/data/archiveDesignSystem.js`. Reconcile `src/components/ArchiveUI.jsx`, `src/styles/archive-system.css`, `docs/DESIGN-SYSTEM.md`, and `scripts/audit-design-system.mjs`.

### 13. Release documentation
Canonical owner: `public/implementation-notes.md`. Reconcile `README.md`, `docs/BUILD-PREFLIGHT.md`, `docs/DESIGN-SYSTEM.md`, and the visible change log when active contracts change.

## Release checklist

### Content integrity
- Chapter endpoint, titles, ranges, and timeline ceilings agree.
- New factual records use approved Hunterpedia/Fandom sources.
- Research depth and evidence state remain truthful.

### Identity and media
- Status and aliases resolve from central records.
- Images depict the named subject and retain provenance.
- Broken media collapses without placeholders.

### Experience
- Dense views remain readable at maintained widths.
- Keyboard, focus, reduced motion, and nonvisual alternatives remain intact.
- Large research data remains outside the startup shell.

### Cloudflare
- `npm run build` passes.
- `dist/server/index.js` and `dist/client/` exist.
- `/api/admin/chapter/session` returns JSON and bypasses `ASSETS`.
- No `.openai`, portable ZIP, standalone, or release-manifest artifact is deployed.
- The exact validated commit reaches terminal Cloudflare success.

## Completion criteria

1. The chapter scope and unequal research depth remain visible.
2. Stable IDs, statuses, sources, evidence states, relationships, and UI primitives have canonical owners.
3. Thirteen maintenance runbooks cover recurring changes.
4. Media and written status remain deterministic and honest.
5. Keyboard, focus, reduced motion, narrow-width safeguards, and alternatives remain explicit.
6. Large data stays outside the startup shell under explicit budgets.
7. Fifteen independent audits report together before deployment.
8. The production artifact contains only the Cloudflare Worker, HxH browser assets, and required metadata.

A local build or repository commit is not proof of deployment. Record hosted success only after Cloudflare completes and the live routes are directly verified.
